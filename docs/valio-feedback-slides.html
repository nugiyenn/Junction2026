Data firewall

What the agent sees, and what Valio keeps

The agent sees

  • Its own customer price
  • Can fill: yes or no
  • Stock confidence, not amounts
  • Allergens, reliability, carbon

Valio keeps

  • List price and discount
  • Supplier
  • Exact stock quantities
  • Internal category codes
Feedback

Is this the right line? Anything else that must never reach an outside agent?

Trust and record

Signed quotes and a record nobody can quietly edit

Signed by Valio

  • Public key at a standard address
  • Price held for 15 minutes
  • The agent verifies without calling Valio

Decision record

  • Every agent and human step, in plain language
  • Each entry hashed with the one before
  • Edits break the chain and show up

It reveals tampering. It does not prevent it.

Live web checks

Allergen claims and recalls, checked against real sources

  • Product pages are read and each claim is kept only if its quote is on the page.
  • The Finnish Food Authority's recall notices are searched for the product.
  • A source that disagrees with the catalog sends the order to a person.
  • Any page can make an order stricter. Only the maker or a known grocery or wholesale site can clear an unknown allergen.
  • Every result shows its source link.

"No recall found" means the search found none, not that none exists.

Feedback

Open interface

Any agent can connect. None can approve.

How agents connect

  • REST API with an OpenAPI description
  • MCP server, seven tools
  • No tool to approve or change a customer's rules
  • Approving on REST needs a key, when one is set

Protecting Valio's API

  • Only a short list is priced live
  • Short cache on price and stock
  • Rate limits per customer

Verifiable receipts

Every order leaves a receipt anyone can check

What is in it

  • The order and quote, as the agent saw them
  • The customer's rules, with a hash
  • The decision and the approver's device signature
  • The record entries, hash-linked
  • Valio's signature over all of it

What a check shows

  • Six checks, run in the browser
  • Change one number and it fails
  • Not proved: the key comes from our server unless you paste one, and a device key is not a named person

It shows tampering. It does not prevent it.

What we have not solved

Honest limits of the prototype

  • Orders stay in our database: the mock has no order endpoint.
  • Approving needs a key, but the agent has no login of its own: callers pass a customer id.
  • A planted sentence on a trusted site could still clear an unknown allergen.
  • Search by meaning covers only part of the catalog.
  • All data is synthetic, so prices, stock and order history are not real.
